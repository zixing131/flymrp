# 在线商店 2640 个应用兼容性回归（2026-09-14）

> 后续更新：请看[第二轮修复与回归](2026-09-14-store-round2.md)及[430 项最新状态](2026-09-14-store-round2-issues.md)。下文保留第一轮历史记录。

本轮针对 `flymrp2` fork 的在线商店测试。原始列表有 **2640 个条目、2640 种不同 MD5 内容**，包括游戏、阅读软件、联网客户端、启动器及插件安装包，不能把全部条目都当成独立单机游戏。没有沿用旧报告中的成功/失败判断。

## 范围与证据

- 商店源：<https://mrpstore.gddhy.net/api/list.json.gz>。本次 gzip 快照 SHA-256：`75b49a39309ece08fc4eabc5c52b40c1151b4c833ec26255736f232427a4dcc9`。
- [冻结清单](2026-09-14-store-manifest.json) 包含条目编号、名称、AppID、下载路径、MD5、长度、分辨率和商店附加资源 URL。AppID 可能重复，定位问题应使用 `caseId + md5`。
- 按 MD5 从本机集合复用 1094 个完全相同的包，其余 1546 个（481,238,967 字节）从商店下载并验证长度与 MD5。没有仅按同名文件认定为同一版本。
- [基线结果](2026-09-14-store-baseline.json) 和 [修复后结果](2026-09-14-store-fixed.json) 各记录全部条目。所有存在问题或需要进一步验证的应用汇总在 [问题清单](2026-09-14-store-issues.md)。
- 完整下载缓存、每包 checkpoint 和详细场景 PNG 保留在本机 `artifacts/compat-20260914/`；下载包不加入 Git。

README 中的“精选 100”是上游历史描述。当前 fork 的 `config/classic-games.json` 是动态生成的 1 个《白跑分》，实际文件在仓库 `mrpfile/`，不在本机合集根目录。本轮保留 fork 清单，未强行恢复上游 100 个游戏。

## 测试方法与限制

每个应用在独立 Node 子进程运行。使用生产 ARM 上限 **128,000,000 条/调用**，单应用宿主 watchdog 为 45 秒；按商店 `scr` 设置屏幕。初始 30 tick，然后依次发送 `SOFTLEFT,FIRE,FIRE,UP,RIGHT,DOWN,LEFT,5`，每键按下/释放后各运行 2 tick，最后再运行 30 tick。每 tick 推进 80 ms，并最多处理 16 次调度。加载项目内置系统组件和本机按包头文件名匹配的 `mythroad_res`，每次从空白存档开始。

判断画面采用 `FrameCapture` 的实际已提交 LCD，不再把尚未刷新到屏幕的工作缓存当成玩家看到的画面。原粗筛只有 1M 指令、3 tick、默认无外部资源，本轮没有使用这些低预算设置。

`input-smoke-passed` **只表示在按键窗口中 LCD 有变化且流程内没有异常**，动画本身也可能产生变化；它不是输入因果验证、通关证明或完整可玩认证。静态/黑屏可能需要触屏、不同按键、额外资源或更长时间；退出可能是来宾主动行为。Node 批测不验证浏览器音频、触屏精度、跨会话存档、真实联网服务和全部关卡。商店有 12 个附加资源链接，本轮只使用现有本地资源，没有声称逐一下载并验证这些资源包。

## 已修复的问题

### 1. ARMv5TE 双字读写缺失

《见缝插针2025》（#22）遇到 `0xe1c300f0`（STRD），《Tom猫》（#203）遇到 `0xe1c320d0`（LDRD），《滚木块》（#806）和《人生重开模拟器》（#1683）遇到 `0xe14b21f4`（STRD）。旧 decoder 把 `L=0, SH=2/3` 当成非法指令。

新增 LDRD/STRD，处理寄存器对、立即数/寄存器偏移、前后索引和写回。非法寄存器对、写回重叠及未对齐访问仍明确报错，不把非法指令吞掉。新增 opcode 放在现有单字访存范围之外，编译块通过解释器回退执行，避免改变现有 opcode 区间含义。

依据 [Arm 架构手册](https://documentation-service.arm.com/static/5f8daeb7f86e16515cdb8c4e) 对 ARMv5TE 实现可选择 word/doubleword 对齐的规定，本实现选择 word 对齐，不采用单字 LDR 的非对齐旋转规则。48 组独立 Unicorn 向量比较了两条执行路径，共 96 次执行，覆盖偏移、索引、写回、条件与 flags；另有真实故障指令和错误路径测试。

此修复消除原指令停点，不自动代表所有上述游戏已完整可玩；例如《Tom猫》和《滚木块》定向复测进入了更长执行路径，需结合后续超时/场景结果判断。

### 2. 可选平台探测错误地终止应用

`mr_platEx` 的 `1004,1112,1401,1402,2600,4200,0x70001,0x70003`，及 `mr_plat` 的 `1006,2500,2506,3012` 现在返回 `MR_IGNORE`，不写虚构输出指针，也不伪装服务成功。依据是本机参考 `rxgj-main/src/mythroad/dsm.c` 的 `mr_plat`（1982–2075）和 `mr_platEx`（2251–2435）：这些未接管命令落入返回 `MR_IGNORE` 的 default。

修复覆盖《Angry Birds》《疯狂的小鸟》、多款 `1112` 探测壁纸应用、部分娱乐城和工具。只对白名单中的已观察探测采用该行为，其余未知 ABI 仍保留诊断异常。

### 3. table[62] 与 table[129]

- `table[62] mr_connectWAP` 是旧平台的 void 通知：参考 `dsm.c:1769–1771` 仅打印日志。现在接收调用，不发起宿主网络请求或打开浏览器网页。
- `table[129] _mr_EffSetCon` 根据参考 `mythroad.c:1233–1253` 实现 RGB565 各通道按 256 缩放，正确读取 AAPCS 栈上的第 5–7 参数；遵守 int16 参数、裁剪及来宾当前离屏缓冲区。Lua 的同一接口也实际修改 framebuffer，而不再仅记录命令。

单元测试检查栈参数、裁剪、颜色、离屏目标和未知命令不会伪造输出。《12530音乐客户端》等样本已越过原来的 required-slot 异常。

### 4. 商店分辨率丢失

旧 `runStoreApp` 丢弃 `scr`，播放器只解析文件名。当前快照有 **7 个条目**被推断成错误尺寸：#78、#80、#143、#144、#145、#1318、#1699。其余大量非 240×320 包的文件名本来就带有可识别尺寸，不能笼统宣称数百款全部受影响。

现在通过播放器 URL、SD 文件元数据、重启参数传递尺寸；旧下载可从本地商店缓存恢复提示。“我的游戏”再次运行也保留元数据。手动设置优先于商店尺寸；新增 128×128、128×160、272×480、480×800 手动选项，并校验元数据范围。12 项回归覆盖全部 10 种商店尺寸、优先级与非法输入。

### 5. 缺少外部资源目录时，播放器把 HTML 当 JSON

浏览器运行《MTK魔法寿司 240×400》时直接复现：`/__resources` 返回空列表后，Vite 对不存在的分组 JSON 返回状态 200 的 HTML 页面；旧代码执行 `response.json()`，整个游戏在启动前失败。

`optionalResourceJson` 将缺失目录和 HTML fallback 当作没有可选资源，继续加载游戏；真正标记为 JSON 的损坏内容仍报错。修复后同一浏览器、同一包实际进入寿司棋盘，状态显示 240×400。

## 浏览器与持续运行复核

浏览器从本地 Vite 页面访问真实商店，下载并运行《MTK魔法寿司 240×400》，确认实际画布尺寸、棋盘和运行状态。随后运行《Angry Birds 272×480》，已从原先启动异常推进到标题、PLAY、关卡选择及第一关弹弓画面，实际画布为 272×480。它仍报告 `Unable to decode audio data`，声音没有通过验证；不能把启动/画面改善写成所有功能兼容。

## 未解决项与判断边界

所有剩余报错、黑屏、静态画面和超时均保留在问题清单，没有将它们改为“已通过”。对以下类别需要继续按具体游戏场景处理：

- Lua 调用非函数/非 table：Luna 对 #29《2010十二星座运势》和 #158《NBA：超经典射篮》的实际失败帧核验到 `pay_getVersion` 中调用不存在的 `file_open_err_Exit`，前序读取 `ydqtwo.mrp`、`*H` 和包名失败。进一步实验让包名可读后仍有后续 Lua 错误，说明不能随意塞一个空函数就宣布修好，也不能直接断言包损坏。
- 明确提示缺少 `start.mr`、SDK key 或不能直接运行的包：需要正确启动器/组件和资源，不能伪造包内容来绕过。
- guest 未映射地址、堆损坏、异常格式串：需要逐包追踪根因；没有把它们吞成成功。
- 联网客户端、浏览器跳转、相机/媒体及附加下载：受平台实现和现有资源范围约束，不代表真实网络服务已经恢复。
- 45 秒超时和静态画面属于需进一步诊断，不等同于永远不能运行。

每完成一个应用就原子写入 `cases/*.json`。相同代码、清单、设置下重跑同一输出目录会跳过已完成项；代码或清单改变时明确拒绝复用，必须用新输出目录。重新诊断下载失败/超时也应使用新输出目录，避免把旧 checkpoint 当成新结果。缓存按 MD5 命名，复测无需重复下载。

本轮也修正 3 项基线已有测试失配：上游固定 100 条和 KaiOS 必须属于 web 精选的断言不适用于此 fork 的动态清单，改为保持非空、唯一、安全路径/哈希及独立 KaiOS 5 条校验；旧 file-chain 断言仍要求 table[39] 不存在，但当前已实现 `mr_ferrno`，已更新断言。没有为使测试变绿而把有效接口撤掉。
